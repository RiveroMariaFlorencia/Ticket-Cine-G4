# 🎟️ CineMaster 🎟️
## 📽️ Descripcion 
- 🎬La pagina va a permitir realizar la compra de entradas.
- 🎞️ Servira para organizar la venta de entradas de cine por pelicula, fecha, horario, sala y asiento.
- 🛋️ Dirigida a jovenes, adultos y familias que desean adquirir sus tickets con anticipacion, consultar horarios de funciones y cartelera disponible.

---
## 👩🏻‍💻 Guia para nuevo miembro de equipo

1. **Como bajo el repositorio?**
> Clona el repositorio remoto a tu local usando el comando:
`git clone https://github.com/RiveroMariaFlorencia/Ticket-Cine-G4.git`

2. **Como hago el flujo de trabajo?**

| N.º | Etapa | Descripción |
|---:|---|---|
| 1 | **Rama principal (main)** | Contendrá la versión estable y actualizada del proyecto. **No se realizarán cambios directamente sobre esta rama.** |
| 2 | **Creación de una nueva rama** | Para desarrollar una nueva funcionalidad o realizar una modificación, se creará una rama a partir de `main`. |
| 3 | **Realización de cambios** | Cada integrante trabajará en su rama correspondiente y guardará los cambios mediante commits. |
| 4 | **Commits** | Los commits deberán seguir la convención definida en el proyecto. |
| 5 | **Subir la rama al repositorio remoto** | Una vez realizados los cambios, se subirá la rama a GitHub mediante `git push`. |
| 6 | **Integración de los cambios** | Cuando una funcionalidad esté terminada, se realizará un Pull Request para revisar e integrar los cambios de la rama correspondiente a `main`. |
| 7 | **Actualizar el repositorio local** | Antes de comenzar una nueva tarea, se actualizará la rama `main` local para trabajar siempre sobre la última versión disponible. |

3. **Como defino la estructura de la descripcion del commit?**
> La descripcion del commit debe ser breve y respetar los siguientes tipos:
> - feat: Nueva funcionalidad.
> - fix: Corrección de un error.
> - docs: Cambios en la documentación.
> - style: Cambios visuales o de formato que no afectan el funcionamiento.
> - refactor: Modificación o reorganización del código sin agregar una nueva funcionalidad.
> - test: Creación o modificación de pruebas.

4. **Como es la dinamica del trabajo?**
> Si la sube x, la verifica y.
> Ej. Si la sube Flor, la verifica Anto.
